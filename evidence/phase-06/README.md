# Phase 06 Evidence Directory

Phase 06 is not complete until a real-model validation run has been inspected, the protocol has been frozen, and the single authorized locked-test baseline has been preserved and recomputed.

Current repository state intentionally contains **no fabricated real benchmark evidence**. The committed `validation-review.template.json` is only a template; its false/default fields must not be changed to passing values without manually inspecting the real validation predictions.

Expected evidence after real execution:

- `validation-gpu-host.json` — sealed GPU/software host evidence captured before real validation.
- `validation-run.json` — deterministic export from the real validation run in PostgreSQL.
- `validation-review.json` — human review covering every validation prediction.
- `protocol-freeze.json` — generated by `scripts/freeze_phase6_protocol.py --apply` only after validation evidence, operational checks, host binding, and review pass.
- `test-gpu-host.json` — sealed GPU/software host evidence captured before the locked test; its stable environment fingerprint must match validation.
- `test-run.json` — deterministic export from the single authorized real locked-test baseline.
- W&B run/artifact references embedded in the final locked-test export.

The run-export checksum covers predictions, metrics, cost records, run/config identity, tracking references, and the exact held-out incident IDs. `scripts/freeze_phase6_protocol.py` refuses to authorize the locked test if validation evidence is incomplete, duplicated, checksum-invalid, scientifically inconsistent with the protocol, technically incomplete, not fully cost-accounted, not bound to sealed GPU-host evidence, or not manually reviewed.

Repository completion state is machine-checkable:

```bash
python scripts/check_phase6_contract.py
python scripts/check_phase6_exit.py
```

`check_phase6_contract.py` accepts only internally consistent states (`pre_validation`, `validation_ready_to_freeze`, `frozen_waiting_test`, or `complete`) and reports the remaining blocker. It is part of `make verify-all` now. `check_phase6_exit.py` is intentionally expected to fail until the complete real evidence bundle exists; it must not be added to the cumulative completion gate or reported as passing before the real locked-test result is preserved.

When the final bundle is complete, the hard-exit checker requires exact held-out prediction coverage with no duplicates, stored-metric recomputation, zero technical inference failures, one versioned cost record per prediction, frozen/recoverable scientific identity, validation/test GPU-host fingerprint equality, and configured W&B run/artifact references for the locked-test result. Paid-rate snapshots must remain strictly positive. The explicitly named `kaggle-free-quota-no-direct-usd-per-gpu-hour` snapshot is the sole zero-direct-cost exception: every cost record must use the same snapshot, record a zero GPU hourly rate and zero marginal amount, preserve positive inference latency, and report zero marginal mean cost. This records Kaggle's actual direct billing semantics rather than fabricating a provider price.
