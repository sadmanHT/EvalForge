# GitLab Versions differ across zonal clusters (Severity 3) **Problem:** GitLab component versions in production were out of sync across zonal clusters. One pod in the us-east1-b zone remained using an older version for hours after a newer deploy had replaced all of the other pods. **Impact:** This turned out to be a false alarm. In general, a version disparity could potentially affect the consistency and reliability of services provided across different zones. Version differences are expected to linger only while deploys are in progress, but in this case it lingered longer. **Causes:** A single pod lingered in a `ContainerStatusUnknown` state. Its containers had all exited, but the pod metadata was stuck in that state. Consequently, no traffic was reaching the lingering pod and there was no customer impact. The pod's webservice container exited because k8s terminated it due to node-level disk space exceeded 90% used. This particular container was not at fault (having used less than 250 MB out of over 100 GB), but it was one of possibly several pods terminated by k8s to reduce disk space usage. This was apparently the only pod that failed to exit cleanly, leading to the spurious alert about running multiple versions of the gitlab container image. **Response strategy:** Multiple deployments have been attempted, and the g_delivery team has been consulted for advice. Affected pods are being investigated for termination to force recreation. Manually terminating the 1 lingering pod resolved the alert. ---- _This ticket was created to track_ [_INC-889_](https://app.incident.io/gitlab/incidents/889)_, by_ [_incident.io_](https://app.incident.io) 🔥
